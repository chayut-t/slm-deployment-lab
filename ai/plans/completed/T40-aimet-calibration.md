# T40: AIMET and calibration environment

Status: completed
Owner: T40 (branch `task/T40-aimet-calibration`)
Updated: 2026-08-02

## Objective

Freeze everything the W8/W4 lane needs before a single quantized weight
exists: a reproducible Linux AIMET environment, a calibration corpus whose
revision and preprocessing are hash-frozen and licensed, and a preflight that
refuses to calibrate until the floating baseline it will be compared against
has been re-verified.

T41–T43 inherit these contracts. A quantization quality delta is only
meaningful if the floating side of the comparison is the artifact we think it
is, and if the calibration inputs can be regenerated byte-for-byte.

## Scope

### In scope

- `environments/linux-aimet/` — exact AIMET, Python, PyTorch, CUDA, and
  transitive pins with the commands that build and verify them.
- `configs/quantization/calibration.yaml` — the frozen corpus contract:
  revision, preprocessing, selection rationale, token budget, licensing.
- `src/slm_lab/quantization/calibration.py` — deterministic corpus
  construction and validation, runnable without any heavy runtime.
- `src/slm_lab/quantization/parity.py` — the pre-quantization baseline parity
  preflight.
- `tests/quantization/` — deterministic preprocessing and parity tests.
- `docs/learning/calibration_and_aimet.md` — the study surface for the
  `LEARN-11` checkpoint, whose id is reserved for T40 by the coordinating
  session while `LEARN-10` is reserved for T21.
- `results/quantization/` — committed, compact parity evidence.

### Out of scope

- Running AIMET. It is Linux + CUDA only; the development host is an Apple M4
  Mac mini. No quantization is simulated, exported, or profiled here.
- Selecting W8/W4/LPBQ/LiteMP policies. That is T41 and T42.
- Choosing the external evaluation corpus for quality deltas. That is T13.
- Installing any heavy dependency into the repository environment.

## Decisions and discoveries

- 2026-08-02: AIMET is deliberately *not* added to `pyproject.toml` as an
  optional extra. `aimet-onnx` ships only a
  `manylinux_2_34_x86_64` wheel, so an extra would make `uv sync --extra` fail
  on the primary macOS host. The AIMET stack is pinned in
  `environments/linux-aimet/` instead, which is where platform extensions
  already live.
- 2026-08-02: the calibration corpus is two-tier. Tier 1 is derived from the
  committed CC0 T10 fixtures and is the only tier that is committed and
  required; tier 2 records revision-pinned public corpora as declared,
  non-committed candidates for T41. This mirrors the
  `external_quality_candidates` pattern T10 already established, and keeps the
  repository free of third-party dataset rows.
- 2026-08-02: baseline parity is enforced as a preflight gate rather than a
  report. The numerical half of parity needs `torch`/`onnxruntime`, which this
  host does not have; the gate therefore verifies artifact identity here and
  records the exact command that completes the numerical half on the CUDA host.
- 2026-08-02 (independent review pass): the AIMET smoke test was re-derived
  from the shipped `aimet_onnx` 2.36.0 wheel. The AIMET docs'
  `libpymo.EncodingAnalyzerForPython` has no Python binding in that release;
  the compiled `_libpymo` Cython module exports only `TfEncoding`,
  `BlockTensorQuantizer`, and `PtrToInt64`. The README now drives
  `BlockTensorQuantizer` and records the `strings` command that lists the
  exported names. AIMET also publishes Windows wheels on GitHub (CPU only), so
  "Linux x86-64 only" was corrected to "no macOS or Apple-silicon build; CUDA
  build only for Linux x86-64".
- 2026-08-02 (independent review pass): the corpus manifest gained a computed
  `calibration_corpus.coverage` block. The four T10 context workloads are
  strict token-ID prefixes of one another (one repeated 602-character seed),
  they carry 83% of the token budget, and the whole corpus touches 175 of
  151,936 embedding rows. Those figures are now measured into the hashed
  corpus, and the per-sample rationales no longer imply embedding-table or
  vocabulary coverage. The corpus hash and `calibration_dataset_revision`
  changed accordingly.
- 2026-08-02 (independent review pass): "AIMET 2.36.0" is ambiguous. The PyPI
  distribution and the GitHub `+cpu`/`+cu126` distributions share a release
  number but differ: PyPI declares `torch==2.12.*` under its `v1-deps` extra
  and records `2.12.1+cu126` in `_version.py`, while the GitHub wheels declare
  `torch==2.13.*` and record `2.13.0+cpu`/`2.13.0+cu126`. Neither is installed
  with its dependencies here, so there is no functional impact, but a run
  manifest must record which distribution was installed, not only the release
  number.
- 2026-08-02 (independent review pass): `released_for_calibration` was renamed
  `released_for_calibration_on_artifact_identity`, and the unreachable
  `verdict == "verified"` branch was deleted rather than left as dead code that
  implies a state the current inputs cannot produce.
